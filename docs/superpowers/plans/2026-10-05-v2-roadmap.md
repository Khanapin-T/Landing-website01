# Ring site v2 roadmap

**Spec:** `docs/superpowers/specs/2026-10-05-ring-site-v2-design.md`

One session = one branch `sNN-<name>` from an up-to-date `main`. Each session gets its own detailed plan file (`docs/superpowers/plans/2026-10-05-sNN-<name>.md`), written at the start of that session, after the author reviewed the previous one. At the end of a session: commit, `git push -u origin <branch>`, report in Russian with screenshots, STOP. The author opens and merges the PR.

## How sessions are executed (agreed with the author)

- Each session is split into tasks by complexity and amount of work. **Every task is owned by exactly one agent**; no two agents work on the same task or the same file.
- Tasks are grouped into **waves**. Tasks inside a wave touch disjoint files and run in parallel; a wave starts only after the previous one is reviewed.
- Model per task by complexity: `quick-worker` (Haiku) for fully specified small tasks, `implementer` (Sonnet) for regular components, `implementer` with the Opus model override for shaders and other hard work. Look-and-feel tuning, integration and browser verification stay in the main session.
- Agents never commit, never run `npm install`, never start a dev server. The main session reviews each task's diff, runs its tests and commits it (author = the user, no AI attribution).
- The read-only `reviewer` (Opus) reviews the whole branch once at the end of each session.

## Rules every act session inherits

- An act owns its folder `src/acts/<id>/`, its HUD copy in `src/content.ts` and its tweens on `master` at absolute positions in screens (`master.to(target, vars, window.start + offset)`).
- While `getAppState().phase === 'loading'`, acts must render **visible** so `Precompile` compiles their shaders; after that, an act is hidden outside its scroll window.
- No React state updates driven by scroll. Read `story` in `useFrame`; animate DOM with GSAP refs.
